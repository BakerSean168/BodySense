## Actual functional scope

- `apps/web/src/features/body-canvas/model/bodyEpisodeAssociations.ts` projects **generated owner-bound BodyFact/BodyEpisode pages** into a bounded selection model; filters to asserted, self-reported symptom Facts with explicit symptom type/presence, carries server-owned `Episode.projection` without inventing ongoing/end or onset.
- `apps/web/src/features/body-canvas/components/BodyEpisodeAssociations.tsx` provides a collapsed optional section in the already live **Person → 身体记录**. Opening queries actual `GET /body-state/records` and `GET /body-state/episodes`. It displays source-backed Episode identity and status, can read earlier revision batches independently, and offers explicit user create/link selection. It is **not** a second source store or an unapproved new main-level Person tab. No automatic AI admission.
- `apps/web/src/features/body-canvas/components/PersonWindow.tsx` mounts the above section only for Records; Habits and all existing category layout remain untouched. Existing `body-canvas.css` gets only constrained native form widths for the 390px viewport.
- An additional explicit **本人症状** form now creates a real source Fact directly in this Person surface. The user enters their own original statement, symptom type, presence (yes/no), and optional side. The form sends `recordBodyFacts` with a separate idempotency key and revision; it never automatically runs an Episode command or guesses an onset, diagnosis or recovery. After a true BodyFact commit it refreshes both owner-scoped read models and only then offers the user a distinct Episode create/link confirmation. An ambiguous symptom save retains its original full request for replay; an acknowledged-but-not-refreshed save is not retried.
- The Episode buttons call the previously verified strict generated `bodyEpisodeService.create/linkFact` with **exact source Fact ID, expected BodyState revision and a single unique command ID**; server still enforces source availability/type/owner/side/unique primary association and durable single transaction.
- If separate records/Episode pages (including older revision batches) disagree on user or `current_revision`, the view **hides combined rows and blocks new commands**. A prospective command can never use an inferred client revision; it uses a jointly validated snapshot. The backend is still final authority for mid-flight edits.
- A transient failure keeps the _same_ `idempotency_key`, original `expected_revision`, Fact ID and Episode ID for deliberate retry, even after the disclosure is collapsed and reopened. An explicit 400/404/409 prompts reread and clears that pending command. A correct owner/Facts/target and revision-confirmed **persisted receipt**, not HTTP dispatch or visual optimism, enables a saved-state message.
- If refreshing data after a confirmed commit fails, the interface reports **committed but refresh unavailable** and never resends the write. The list is invalidated under the existing `workspace` React Query tree.
- Switching authenticated users cancels old UI intent and suppresses late cross-account success notices. Read-only or unauthenticated windows render no mutation controls.

## Supported display and failure states

| Situation                           | Visible behavior                                                                                                               | Allowed action                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------- |
| Collapsed                           | Single `查看与关联经历` action inside Records, no query until opened                                                           | Expand                                              |
| Loading / fetch failed              | Progress / error without saying 'no episodes'                                                                                  | Refresh                                             |
| No source-visible Episode           | Qualified empty message **for loaded scope**, not global absent diagnosis                                                      | User-selected create from asserted positive symptom |
| No eligible positive symptom        | Show no eligible current-record candidate                                                                                      | Read older Facts / add accepted Fact elsewhere      |
| Explicit negative symptom           | May be linked as an **observation** to a user-selected compatible Episode; never creates a new identity or marks episode ended | Manual link only                                    |
| Conflicting owner or revision pages | Hide inconsistent combined projection; disable new command                                                                     | Refetch both sources                                |
| Valid create / link                 | Persist receipt; then invalidate and refresh fact+episode read models                                                          | Continue after confirmation                         |
| Network uncertainty                 | Preserve exact original command for replay                                                                                     | Retry original request                              |
| 400/404/409                         | Preserve draft selection but discard invalid retry identity                                                                    | Refresh then reselect, new semantic action          |
| Commit confirmed, reload failed     | Distinct committed-but-refresh-failed notice                                                                                   | Refresh only; never resend write                    |
| Source blocked/withdrawn by server  | No source-visible Episode; 404/empty according to canonical read contract                                                      | No forged data or status                            |

## 2026-10-13 · Component ownership and ambiguous-source hardening

The initial functional vertical has now been refactored **without a wire/schema change**. `hooks/useBodyEpisodeController.ts` is the single React Query/read-snapshot, explicit intent, revision, stable retry and receipt orchestrator. The host `BodyEpisodeAssociations.tsx` only composes the Person disclosure, progress/notice states and actions; `BodyEpisodeList.tsx`, `BodyEpisodeSymptomForm.tsx` and `BodyEpisodeAssociationForm.tsx` are purely presentational and receive validated values and callbacks. This leaves the eventual independent Penpot Episode floating window free to reuse the same read/write orchestration without copying domain logic.

Four regressions were written **red first (4/4 failed on the prior 2904b61f4 source)**, then made green: (1) an initially failed source read can never render an empty Episode history; (2) an errored background refetch with cached pages cannot enable new mutation or show success-shaped emptiness; (3) a network-uncertain Episode write locks its target selection until the exact original key resolves; (4) a network-uncertain source Fact write locks the original symptom statement, presence and laterality, and also blocks starting an independent Episode command. The user can still retry the original command after collapsing/reopening the disclosure. The server remains authoritative; UI locks are additional safety, not a replacement for Go transaction guards.

# PC-001 · Enforce one Conversation and one serial Run

Status: QUEUED / NOT ADMITTED. Phase 1. SF cross-reference: SF-30.
**Owner role:** Chat Runtime Owner. **Dependencies:** `INT-001`.
**Exclusive resources:** `conversation-schema`, `public-openapi`.

## Goal and why now

Enforce one Conversation and one serial Run. This is an execution slice under the approved BodySense V2 Master; it does not approve clinical decisions or establish any readiness gate by itself.

## Scoped paths / ownership

- `apps/api/internal/service/conversation_service.go`
- `apps/api/internal/repository/conversation_repository.go`
- `apps/api/internal/transport/httpapi/conversations.go`
- `apps/web/src/features/consultation/**`

**Out of scope:** Other owners' dirty worktrees, unrelated source files, direct production changes, automatic clinical authorization, and any unapproved legacy contract restoration. Public OpenAPI, generated clients and migrations require a serialized designated owner before mutation.

## Ordered implementation

1. Characterize existing multi-conversation rows/routes and retained Ask User original-Run resumes.
2. Define one-user-one-conversation persistence and concurrent active-run lease semantics with additive migration.
3. Update Go/public API and UI only after old links, source references and new singleton identifiers are verified.
4. Cover second-device starts, pending AskUser, retries, sign-out and old public sharing denial.

## Verification commands and negative cases

- Go conversation repository/service tests with -race and isolated PG18
- Real browser cross-device pending AskUser and replay

## Acceptance evidence

- One conversation is enforced at DB and API boundaries; only one active Run per user.
- Resume/cancel/reload retains original Run and no public health sharing path remains after verified retirement.

**Required handoff:** execution identity/model; actual cwd/branch; input and output exact SHA; changed file list; tests with exit codes and logs; uncommitted diff disclosure; code review; pending gates/owner. Only an Integrator may accept a new shared schema/contract into the integration candidate.

**Protected invariants:** owner identity and source provenance; commit receipt before success; revision + idempotency; source deletion distinct from erasure; Go-owned medical authority and fail-closed Safety; one writer per checkout. No invented Diagnosis Q-17 TTL, clinical thresholds, or old BodyConcern.

**Scheduling constraint:** even when DAG dependencies pass, do not run in parallel with any other ticket sharing `conversation-schema` or any other listed exclusive resource. Ticket does not authorize T3 to use canonical root as a shared writer.

## PC-001 bounded persistence reader — fail-closed singleton admission

The approved PC-D4 and PC-D5 contract requires one stable per-user
Conversation but **does not** authorize choosing or merging existing legacy
Conversation IDs. The first non-mutating Go repository seam is:

- `ConversationRepository.GetSoleLiveByUserID(ctx, userID)` — owner-scoped,
  parameterized and read-only. Returns `nil, nil` only when there is
  **no historical Conversation row** (future lazy creation), the original
  Conversation only when it is the sole historical and non-deleted row,
  `ErrLegacyMultipleLiveConversations` for two or more live rows,
  and `ErrLegacyConversationHistory` for deleted-only or mixed history.
  A missing/empty owner is rejected before making a database call;
  database failures are not mistaken for missing data.
- The query uses a bounded `LIMIT 2` and PostgreSQL
  `deleted_at NULLS FIRST` ordering. Archived/paused rows still count;
  a soft-deleted historical identity **blocks** silent recreation and stays
  available to the separate reference/erasure audits.
  It does not use `last_message_at` and does not guess a newest, oldest or
  surviving canonical ID.
- `conversation_singleton_preflight_test.go` covers empty owner,
  absent Conversation, archived row, two legacy rows, deleted-only and
  mixed history (three separate negative cases), anonymous error
  identity and database failures via SQLMock.
- `conversation_singleton_preflight_integration_test.go` exercises
  the actual current PostgreSQL 18 schema with a synthetic owner,

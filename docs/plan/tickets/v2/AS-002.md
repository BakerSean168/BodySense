## Goal and why now

Implement verified erasure of source and controlled copies. This is an execution slice under the approved BodySense V2 Master; it does not approve clinical decisions or establish any readiness gate by itself.

## Scoped paths / ownership

- `apps/api/internal/repository/privacy_erasure_repository.go`
- `apps/ai-service/src/** (checkpoint/controlled cache only)`
- `docs/plan/active/2026-10-13-v2-integration-release.md`

**Out of scope:** Other owners' dirty worktrees, unrelated source files, direct production changes, automatic clinical authorization, and any unapproved legacy contract restoration. Public OpenAPI, generated clients and migrations require a serialized designated owner before mutation.

## Ordered implementation

1. Define separate source removal versus health-data erasure commands and receipts.
2. Build controlled-copy inventory for DB, audit/outbox minimal references, checkpoints/cache/index, objects and derived records.
3. Return completion only after qualified erasure verification; preserve unrelated sources and independent clinical decisions.
4. Cover concurrent writes, failures, cross-device references and rollback/retry.

## Verification commands and negative cases

- Native PG18 full removal/rollback/tenant concurrency
- Python checkpoint-cache and Browser deletion negative E2E

- No premature erased success; no unrelated source/evidence loss.
- Deletion results include verifiable receipt and outstanding partial failures.

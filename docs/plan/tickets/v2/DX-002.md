## Slice 1 frozen persistence contract · DX-001 · 2026-10-16

Authority: `docs/product/domain/diagnosis.md` §§3.0–3.7. This is storage groundwork,
not a decision API, evidence-admission authority or a readiness promotion. The
2026-10-16 remaining scope above supersedes the historical numbered-migration and
rollback instructions. No compatibility write, feature flag or Q-17 TTL is added.

| Object / table | Frozen fields and semantics |
| --- | --- |
| Diagnosis / `diagnoses` | `user_id` PK (one per owner), `current_revision` ≥ 0, `created_at`, `updated_at`. Revision zero is empty; adopted count is derived. |
| ConditionEntry / `condition_entries` | `(user_id,id)` identity; `medical_name`; nullable `concept_ref {system,code,display?}` and `qualifiers {regionIds?,laterality?,notes?}`; nullable `assessment {level:suspected\|likely,rationale,informationGaps[],differentialNotes[],basedOnRunId}`; `source_claim_refs[]`; `cause_analysis {summary,rationale}`; `information_gaps[]`; `handling_plan {summary,actions[],cautionNotes[]}`; `disposition:adopted\|inactive`; `latest_decision_id`; nullable `last_analysis_run_id`; `created_at`, `updated_at`. No generic lifecycle or clinical certainty enum. |
| SourceClaimRef (entry snapshot) | `claimId`, `sourceKind:user_suspicion\|agent_analysis\|user_reported_clinical\|clinical_document`, `sourceId`, required nonempty `sourceVersion`, `statement`, optional `assertedAt`, `recordedAt`, optional `evidenceAdmissionId`, `validityAtAssessment:current\|corrected\|withdrawn\|ineligible`. Multiple claims coexist; clinical statements may have no AI assessment. Source kind is per claim, never a lossy single entry column. Current availability is queried from the source owner. |
| EvidenceRef / `condition_entry_evidence` | Owner + condition + `evidence_type:body_fact\|body_observation\|symptom_episode\|document_evidence` + `evidence_id` + required `evidence_version` + `role:supporting\|counter\|context`, `rationale`, `analyzed_by_run_id`. Version is serialized as a decimal string in JSON and stored as a positive bigint in the link. Fact/observation version is immutable `created_revision`; episode version is the frozen BodyState revision at assessment (not a guessed episode counter); document identity is an immutable `document_indicator_reviews.id`, version `1`, with `document_review_action:confirm\|correct`. Typed generated IDs have composite owner FKs to the actual source tables; document review action excludes rejected candidates. |
| ConditionAnalysisRun / `condition_analysis_runs` | `(user_id,id)`, `request_message_id`, `request_evidence_id`, `request_source_version` (versioned user statement preserving the request through chat pruning); `trigger:new_analysis\|partial_update\|full_reanalysis`; `scope {conditionIds[],evidenceRefs[],description}`; `based_on_body_state_revision`, `based_on_diagnosis_revision`; `input_evidence_refs[]`; `agent_hypotheses[]`; frozen `replay_input`, `execution_provenance`; `idempotency_key`, `request_fingerprint`, `started_at`. This is a new formal analysis identity, not a legacy DiagnosisAnalysis or chat Run. No mutable Run state in the base row. |
| ConditionProposal / `diagnosis_proposals` | `(user_id,id)`, `run_id`, nullable `target_condition_id` (create has none), `change_kind:create\|update\|set_disposition\|update_relation`, immutable `content {proposedEntry?,changeSet?,newDisposition?,dispositionReason?,relationChange?}`, `content_fingerprint` (SHA-256 of exact operation/target/content/source versions), `base_revision`, `evidence_refs[]`, `counter_evidence_refs[]`, nullable `supersedes_proposal_id`, `created_at`. No default timeout or `expires_at`. |
| Decision / `diagnosis_decisions` | `(user_id,id)`, `proposal_id`, `run_id`, exact `content_fingerprint`, `decided_evidence_refs[]`, `decision:accept\|reject`, `tool_call_id`, `decided_at`; `idempotency_key`, `request_fingerprint`, `expected_revision`, unique `receipt_id`. One decision per proposal. Composite FK binds exact owner/run/proposal/content/base revision. Decision receipt = these persisted identity/authorization fields; it acknowledges only recording a choice, never Diagnosis adoption. |
| DiagnosisRevision / `diagnosis_revisions` | `(user_id,id)`, unique `(user_id,revision)` with `revision=previous_revision+1`; `previous_revision`, `revision`; exactly one of `run_id` / `direct_edit_id`; nonempty exact `patch[]`, `decision_ids[]`, `body_state_revision`, `evidence_refs[]`, frozen `replay_input`, `execution_provenance`, `idempotency_key`, `request_fingerprint`, unique `receipt_id`, `committed_at`. One revision per formal Run. This row is the commit receipt; a decision receipt cannot substitute for it. Direct-edit authorization storage/validation belongs to DX-003; no direct-edit writer is exposed here. |

JSON nested fields follow the domain names above (camelCase); relational columns
use snake_case. UUID references across the new relational tables always include
`user_id`. BodyState/document source qualification and current availability must
be revalidated by Go before slice 2 commit; a source FK proves identity/version,
not clinical eligibility. A document indicator review alone never proves a
clinical diagnosis statement. Claim snapshots and proposal JSON are not alternate
fact stores or authorization shortcuts.

Run/Proposal bases, Decision, Revision and frozen replay/provenance reject SQL
UPDATE. Entry/evidence rows are committed projections, not mutable AI output.
Append-only events (including rechecks, supersession/expiry and the single Run
terminal outcome) and state projections belong to slice 2. There is no repository
operation here that writes a ConditionEntry, decision or revision. Slice 2 must
validate exact JSON content/claim admission and owner-bound references, serialize
against current Diagnosis and Go Safety, settle every proposal, recheck each
decision after supplemental evidence and atomically write one patch/receipt or
none. Missing/unavailable/stale Safety fails closed; urgent terminal analysis
always has zero revisions. No-op/all-rejected yields no empty revision. Pending
choices and closing Chat do not change Diagnosis. Replay uses only frozen input.

Slice 1 repository seam: idempotent empty aggregate initialization; owner-scoped
head/condition/evidence/proposal/decision-receipt/revision reads, participating in
caller transactions via `database.FromContext`. Missing and foreign IDs return
the same `ErrDiagnosisNotFound` (HTTP 404 mapping is slice 3); the repository has
no HTTP route. Tests seed explicit authorized history directly in disposable
PostgreSQL to test storage/read boundaries without implementing slice 2 early.

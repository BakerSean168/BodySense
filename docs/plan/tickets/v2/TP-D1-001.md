Status: DONE (dormant code only) at main `e4160a9c755455ffe9277af2caba88f62df1a032`. Phase 1. SF cross-reference: SF-50. Issue [#268](https://github.com/BakerSean168/BodySense/issues/268) stages 1–2.

Recorded retroactively by the 2026-10-15 [alignment audit](../../active/2026-10-15-v2-implementation-alignment-audit.md): this work merged as PRs #270, #271 and #273 without a queue entry.

## What was accepted

- `TrainingService` `WithIndependentTrainingPlans()` opt-in; **no production constructor enables it**. Legacy `SupersedePlansExcept` behavior unchanged by default.
- `GetActivePlanByUserID` bounded `LIMIT 2`; multiple active rows return `ErrMultipleActiveTrainingPlans` instead of an arbitrary plan.
- `LockOwnerForPlanActivation` owner-row lock inside the outer transaction plus package-private context witness.
- Offline PG18 forward/reverse preview scripts under `scripts/plan/sql/` — **not** in `apps/api/migrations/`.
- Details and native receipts: [`2026-10-14-tp-d1-legacy-multi-active-handoff.md`](../../active/2026-10-14-tp-d1-legacy-multi-active-handoff.md).

## Not accepted (carried into TP-002 / TP-003)

- Live migration of `idx_training_plans_user_active`, explicit Plan-ID selection in Workspace/UI, PlanProposal/TrainingPlanRevision runtime, owner-approved reverse-migration policy.
- **Review finding Q1 (P1):** the owner lock uses `FOR UPDATE` on `users`, which conflicts with the `FOR KEY SHARE` taken by every FK insert referencing that user. Switch to `FOR NO KEY UPDATE` or a transaction-scoped advisory lock and add a non-blocking-child-insert PG18 test **before** the option is wired.

No Training/Safety domain gate is raised by this ticket.

### Matrix notes

- **Deviation · disk:** the host had ~1–2 GiB free (filled by other projects' Docker builds), so `verify:release` ran with `BODYSENSE_VALIDATION_MIN_FREE_GIB=1` instead of the 8 GiB precheck. Go build cache and temp files were moved to `/dev/shm`, and so was Chromium's TMPDIR for the 390 run and the re-runs. Nothing belonging to another project was deleted.
- **Deviation · 1440 re-run:** 4 failures came from host contention or exhaustion, not from the product. They ran under load average 12–16 from another project's vitest and Playwright jobs: `body-explorer:11` hit its 360 s WebGL budget, `desktop-window-dock:191` hit a renderer crash, `legacy-share-retired:12` hit `ERR_INSUFFICIENT_RESOURCES`, and `training-plan-window:188` got the body-profile read-error page. All 4 passed in isolation on the same SHA and stack with no code change. The same suite was 52/52 in CI.
- **Deviation · 390 desktop-only specs:** `body-explorer:11` and `body-explorer:367` open the explorer from the desktop Tools rail. `longitudinal-health:16` used the desktop-only `.bc-business-window` class; at 390 the window renders as `.bc-business-sheet`. The closeout PR pins body-explorer to 1280×720 (its main test checks 390px itself) and moves longitudinal-health to the viewport-neutral `[data-window]` hook. With those pins the 390 project ran 4/4. In the 1440 project `body-explorer:11` hit the contention budget once more.
- **Deviation · DR step:** the first production-DR run failed only because `TMPDIR=/dev/shm` is not visible to the dockerised PG18 client wrappers. It was re-run on the same SHA with the default TMPDIR and passed.
- **Hygiene finding (not fixed):** the `eval:diagnosis-promotion` run inside `verify:release` rewrites `apps/ai-service/data/evals/reports/diagnosis_promotion_readiness.json` (it adds `"identity": {}`), leaving the tree dirty. It was reverted before the dry-run; the committed report should be regenerated.
- **Register-page timeout at 1440:** the root cause was Chromium `ERR_NETWORK_CHANGED` from Docker veth churn on the host, which aborted the entry module graph. It is fixed in the product by #388 (boot recovery).

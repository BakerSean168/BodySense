# Episodic S6-B — owner note controls behind a default-off flag

Parent: [#498](https://github.com/BakerSean168/BodySense/issues/498) ·
user controls [#516](https://github.com/BakerSean168/BodySense/issues/516) ·
ADR #495. S6-A delivered the durable owner-only
[database/repository boundary](./episodic-s6a-user-note-deletion.md); S6-B
adds the public API and the Person preview on top of it.

## Delivery boundary

Two protected operations join the canonical OpenAPI contract:

- `GET /api/v1/profile/episodic-notes` lists the authenticated owner's active
  `shadow` notes, newest first. The projection contains only `id`,
  `contentText`, `fromSeq`, `toSeq`, `status`, `generatorVersion`,
  `retentionPolicyVersion`, `createdAt` and `updatedAt`. It never exposes
  source message IDs, source asset IDs, the user ID or the Conversation ID.
- `DELETE /api/v1/profile/episodic-notes/{noteId}` removes one owned note. It
  reuses S6-A semantics: the selected note and every overlapping note in that
  Conversation are deleted atomically, a content-free tombstone prevents
  regeneration of the source window, same-owner repeats are idempotent, and
  foreign/unknown IDs are indistinguishable owner-masked 404s.

Both success responses carry `Cache-Control: no-store`. Errors use the
existing `ErrorEnvelope` and `strictOpenAPIConvert` boundary. Unauthenticated
calls are 401. While the feature is off the handlers return 404, so the
surface is externally indistinguishable from an absent route.

Deletion here is **not** BodyState or clinical-fact erasure and **not** account
data erasure. It changes no Diagnosis, Safety, TrainingPlan, raw chat or
clinical evidence row. No note is served to a model in this slice (S4 remains
out of scope).

## Feature flag

The whole API+UI surface ships dark and is enabled only by explicit opt-in:

| side | mechanism | default |
| --- | --- | --- |
| Go API | `EPISODIC_NOTES_CONTROLS_ENABLED` environment variable (`true` or `1`) | off |
| Web | `VITE_EPISODIC_NOTES_CONTROLS_ENABLED` build-time Vite variable (`true` or `1`) | off |

There is no server-wide feature-flag service in the repository. The closest
episodic precedent is S2-A's repository-level
`WithShadowAdmissionEnabled`, which is not wired to `cmd/server`, so S6-B uses
the smallest explicit environment switch and injects the parsed boolean through
`WithEpisodicNotesControls`. The Web side follows the repository's existing
`VITE_` configuration pattern. The Web flag is on in the browser E2E job and in
the Nightly candidate Web bundle, so the staging channel can review the Person
记忆 category. Stable release and production deployment promote those exact
candidate digests without rebuilding, so a production Web bundle also ships the
category; availability stays governed by the API switch, which remains off
there (the routes answer as absent).

## Person preview and copy

The Person category picker keeps exactly its five established categories when
the Web flag is off (`PROFILE_CATEGORIES` is unchanged). When on, it appends a
sixth category, 记忆, whose panel lists each note's content, creation date,
source range as 对话第 X–Y 条, and the storage status 仅保存，不参与对话.

The category has no add action. An empty list says 还没有记忆 and explains that
these are conversation memories, not body records, and are not used for
diagnosis. Read failures use the shared Person error surface; deletion uses
`PersonConfirmDialog` and states, verbatim:

> 删除后这条记忆会被永久移除，且不会被重新生成。这不会删除身体记录等临床事实，也不是账号数据清除。删除不可撤销。

After a confirmed delete the row disappears immediately and the authoritative
list is refreshed. A 404 on an already-removed row is treated as gone, not as
a successful clinical change.

## Not authorized

This feature does not authorize:

- Reading notes into any model context, retrieval index or Agent tool (S4).
- Note generation, backfill or changes to S2 defaults and rollover.
- Mutating BodyState, Diagnosis, Safety or TrainingPlan logic or evidence.
- Health-data erasure, full account erasure or source-statement/source-asset
  erasure through the note delete action.
- A database migration. S6-A's schema and tombstones are used as-is.
- Enabling the surface on real accounts, staging or production before product
  and privacy owners approve copy, consent and retention.

## Evidence

- Contract: two operations, camelCase projection, `no-store`, 401/404/500
  envelopes; Go and Web clients regenerated by `pnpm contracts:generate`;
  Postman collection regenerated.
- Go handler tests: unauthenticated 401, owner-scoped list, forbidden-field
  absence, foreign/unknown 404, idempotent same-owner delete, disabled 404 with
  no repository call, default-off env parsing.
- PostgreSQL 18 HTTP integration: real repository behind the generated routes,
  newest-first owner list, no provenance leakage, masked foreign/unknown
  deletes, repeat delete 200, tombstone/row counts, disabled and anonymous
  behaviour.
- Web: generated OpenAPI service contract test, component tests for list,
  empty, error, confirmation copy and removal, and a category-menu test proving
  the five-category list is unchanged while the flag is off.
- Browser: a Playwright spec at 390px enables the test-only flags, seeds inert
  shadow rows into the disposable E2E PostgreSQL (there is no public note
  creation route), verifies list/provenance/status, geometry and a full delete,
  then re-reads the owner API to prove the removed note does not return.
  Product/privacy sign-off remains the gate before real-user enablement.

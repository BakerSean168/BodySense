# 情景记忆混合方案（产品定案与实施细化）

> 状态：**已批准** — 产品负责人 2026-11-05 批准混合记忆方案、记忆查看/删除能力与
> S4 实时召回要求。
> 关系：本文件是 [ADR: Provenance-Bound Episodic Continuity](./episodic-continuity-decision.md)
> （#495）的实施细化，不修改 ADR 的任何既有决定。ADR 仍对临床权威边界、来源
> 追踪与分阶段门禁负责。
> 关联：#515（S2 影子生成）、#517（S4 召回/评测）、#516（S6 记忆界面）。
> 运行时影响：无。本文件与同批测量基础设施不改变任何默认值、接口或服务路径。

## 1. 范围与不可让渡的边界

- 情景记忆是**非权威对话上下文**，与今天的 `ConsultationHistoricalMessage`
  同级：可以说“你之前提到过 / 我们聊过”，但不能成为 Diagnosis、Safety
  screening 或 TrainingPlan 接受逻辑的输入，也不能在没有用户正常陈述路径的情况下
  派生 BodyFact、Observation 或 ConditionEntry。
- 笔记与 BodyState 冲突时 **BodyState 优先**，笔记按过期叙述处理并在提示中标注。
- 记忆不是临床事实，删除一条记忆也不等于健康数据删除。界面文案必须区分
  “对话记忆 / BodyState 事实 / 隐私擦除”三种语义。
- 本方案只讨论*如何存、如何写、如何取*；*能否服务*仍由 ADR 的 Stage 2 门禁
  决定（S2 影子生成只写不服务）。

## 2. 三层记忆模型

| 层 | 载体 | 内容 | 是否权威 | 生命周期 |
| --- | --- | --- | --- | --- |
| L1 结构化常驻偏好块 | Go 拥有的结构化记录（按 key 存储） | 回复风格、称呼、语言、格式等可枚举偏好；少量、稳定、可按键更新 | 否（偏好，不是健康事实） | 长期常驻，按键取代并留痕；不随聊天窗口滚出 |
| L2 PG 情景笔记 | `episodic_notes`（现有 S1 schema） | 即将离开原始上下文窗口的对话片段的有界叙述 | 否 | 有界滚动；按上限从最旧开始滚出；只追加 |
| L3 关键词检索 | 评测/服务层的检索逻辑，读 L2 | 按词法相关性召回 Top-K 笔记 | 否 | 无独立存储；随 L2 生命周期 |

**向量不是第四层，也不是一种存储类别。** 如果未来启用，向量只是 L2 同一张
`episodic_notes` 表上的 pgvector 列与索引，用于给同一批笔记排序；不新建向量库、
不新建第二套记忆权威、不把向量当唯一副本。向量是派生副本，必须满足与笔记相同的
擦除与验证要求（见 §6 门 4）。

被明确排除的形态：独立向量数据库、外部记忆服务、永久不限量摘要库、Python
checkpoint 作为记忆真源。

## 3. Redis 只作可重建缓存，不作记录

- 允许：会话、限流、短期检索缓存（带 TTL）、现有的认证撤销墓碑。
- 禁止：把笔记正文、结构化偏好、向量或“待写入记忆”只放在 Redis；禁止把 Redis
  当作唯一队列或唯一事实来源。
- 判定标准：**清空 Redis 后，记忆必须能从 PostgreSQL 完整重建，且不产生新的
  记忆缺口。** 缓存未命中只影响延迟，不影响正确性或留存。

## 4. 写入触发

三种触发，按可靠性从高到低：

1. **清理边界保底（默认路径）。** 当上下文起点 `C` 越过一个片段、该片段即将被
   prune 时，先落库一条笔记，**或**记录一条内容无关的“缺口”标记；两者必须先于
   清理完成。生成是尽力而为：生成失败、超时或校验不通过都不得阻塞、回滚或延迟
   prune；此时留下缺口而不是留下错误记忆。S2-A 的 owner 锁、来源完整性校验、
   范围幂等与只写 `shadow` 的约束继续有效。
2. **用户明示“记住 / 忘掉”。** 明示记住优先落到 L1 结构化偏好或一条显式笔记；
   明示忘掉走 S6-A 的删除与抑制标记，阻止后续版本或直接 SQL 复活同范围笔记。
3. **夜间非破坏性整理。** 只做去重、合并重复偏好、按上限滚动、按策略版本重评估；
   不新增临床结论、不改写历史笔记正文、不改变用户可见语义。任何需要改变内容的
   整理都必须产生新版本并保留旧版本，直到其正常滚出。

## 5. 更新规则

| 对象 | 规则 |
| --- | --- |
| L1 结构化偏好 | **按键取代并留痕**：同 key 新值生效，旧值保留为历史版本（含生效时间与来源），可审计、可回滚；不做原地覆盖而无历史 |
| L2 情景笔记 | **只追加**：不原地编辑；需要修正时生成新版本并标注 policy version，旧版本按上限滚出；删除是整条删除，不是改字段 |
| 矛盾信息 | **双留并标注日期**：新笔记与旧笔记冲突时两条都保留，各自带日期与来源范围；不静默选一个“正确版本”；涉及临床时以 BodyState 为准并在提示中标注笔记已过期 |

## 6. 实时召回预算与向量启用门

### 6.1 实时预算（S4）

- 召回只在数据库内完成，目标 **库内毫秒级、p95 ≤ 50 ms**。
- **100 ms 硬超时**：超时即降级为“本轮不带情景记忆”，绝不阻塞或拖慢聊天主路径。
- 热路径**禁止调用外部 embedding 接口**；任何网络依赖都不得进入聊天请求链路。
- Top-K 固定为 8 条笔记，摘录有界；召回结果必须标注“非权威、可能过期”。

### 6.2 向量启用五条量化门（全部满足才可讨论启用）

1. **召回缺口**：优化后的关键词 `recall@8` < 0.85，**或**改写片 `recall@8` < 0.75。
2. **混合增益**：混合检索相对关键词整体提升 ≥ 10pp、改写片 ≥ 15pp，且任一分片
   退化不超过 2pp。
3. **延迟**：本地 embedding 方案下召回链路 p95 ≤ 150 ms（含向量查询）。
4. **删除可验证**：完成一次删除演练，证明向量副本随笔记/来源删除而消失，且
   无法通过重建索引复活。
5. **真实规模与伤害压力存在**：在足够规模、足够歧义、且有明确误召回伤害的场景下
   复现门 1–2；仅靠合成且词面可分的语料不算。

当前基线（见 [S2 基准与召回评测](./episodic-s2-benchmark-recall-eval.md)）显示：
规定的 pg_trgm/FTS 关键词路径在中文上只有 `recall@8` 0.61、改写片 0.45；但加入
评测专用的字符二元组对照后达到 0.869 / 0.80，**未触发门 1**。因此当前结论是
**不启用向量**，先完成关键词路径的中文化（不得直接依赖原生 `to_tsvector('simple')`
或三字 `pg_trgm`），并在更难但仍合成的语料上复核门 1–2。

Phase 3 不是默认路线。任一门不过即停在 Phase 2，并把结论写回 Issue，而不是降低门槛。

## 8. 已定与待定

**已定（产品负责人 2026-11-05）**

- 用户可以**查看和删除**自己的情景记忆；删除单条记忆不等于健康数据擦除。
- S4 召回必须**实时**完成，不得异步补记忆或延迟回复。
- **默认保留上限为 96 条 / 32,000 字符**，按最旧优先滚动、条数与字符双限、按 rune
  计数。依据 [S2 基准与召回评测](./episodic-s2-benchmark-recall-eval.md)：
  96 / 32,000 档在 12 个月后保留 81.6%（712/873）的合成笔记。此前
  48 条 / 16,000 字符仅为 test-only 临时值，不是政策。

**待定**

- **数据外发路线**：笔记文本是否可能进入任何外部模型或 embedding 服务尚未决定；
  在此之前，热路径与离线生成都不得外发真实用户文本。

## 9. 非目标

- 不新建向量数据库、不引入第二套记忆权威。
- 不让记忆参与临床决策、安全筛查或训练计划接受。
- 不把 Redis、Python checkpoint 或模型上下文当作记录真源。
- 不因为本文件而启用 S2 生成、S4 服务或任何用户可见入口。

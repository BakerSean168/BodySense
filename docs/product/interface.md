# BodySense · UI 与交互规格

**本文件定义窗口、交互与平台要求。** 业务规则见 [产品需求](./requirements.md)，数据见 [领域模型](./domain/README.md)，Agent 流程见 [Agent 工作流](./agent-workflows.md)。视觉基准是 Penpot 文件 **BodySense · Product Design** 的 Product 页（见 §8）；设计稿中的旧窗口名按 [术语表 §3](./glossary.md#3-penpot--旧代码名称对照) 换算。

## 1. 核心空间

~~~text
交互工具层：人体点选 / 涂抹 / 动作查看 / 临时确认
业务窗口层：Chat · Person · Diagnosis · TrainingPlan · Trainer
底层桌面：持续存在的可交互 3D 人体 Canvas
~~~

3D 人体是持久空间场景；用户移动、收起或关闭业务窗口即可查看人体，不需要先进入一个人体页面。Chat 是自然交流与操作意图入口，不要求永久占据固定左侧或另一侧业务分屏。业务窗口可按任务独立打开，支持合理的拖动、收起、聚焦与恢复。

窗口打开/关闭或工具模式切换不应丢失：

- 当前聊天、等待回答的交互工具及其恢复状态；
- 当前选中的身体部位和区域上下文；
- 打开的业务对象与未完成操作；
- 当前训练计划的准确身份和用户授权状态。

## 2. 业务窗口

| 窗口（Penpot 旧名） | 默认内容 | 主要动作 |
| --- | --- | --- |
| Chat（Assistant） | 每用户唯一持续对话的近期滚动消息、当前 Run、已保存反馈和阻断式 Ask User | 描述身体、提问、发起正式分析、请求计划调整；不提供会话列表或新建会话 |
| Person（Profile） | 当前基础资料、身体记录、器材和相关个人资产 | 查看、纠正、补充、管理个人资料 |
| Diagnosis（Assessment） | 唯一当前综合诊断，按病情独立展开 | 查看依据、补充信息、从 Chat 请求局部重新分析 |
| TrainingPlan（Training） | 该计划当前已接受的动作/强度/频率/安排 | 查看、请求局部修改、接受或暂不采纳建议 |
| Trainer（Workflow/Training） | 当前计划某次课的执行：当前动作、组次、计时与动作演示（§5.1） | 开始/暂停/恢复/跳过、记录完成与反馈、查看安全约束 |

组件的布局、间距、动效和层级与 Penpot 的实际可编辑组件保持一致。本文件定义数据与交互语义，不规定另一套视觉样式。

### 2.1 Chat 单会话与 Ask User 输入区（PC-D4/D5/D9）

- 每用户唯一 Conversation；切换窗口、刷新或换设备返回同一条 Chat 时间线。只展示近期滚动历史，超出安全窗口且持久化完成的旧消息逐步退出 UI；不出现多会话列表、新建、标题、归档或置顶控件。
- 普通情况下，底部为文字/允许附件的常规输入区，显示当前 AgentRun 的流式进度。一个 Chat 同时至多一个活动普通 Run；正在运行时重复发送和跨设备并发应由后端拒绝或定位回同一活动任务。
- Agent 调用 Ask User 时，**底部普通输入区整体替换为本工具的选项及允许的自定义解释输入**。不再在选项卡旁同时暴露普通聊天框，也不将自由补充变成另一个 Chat Run。选择绑定准确 interactionId/runId/toolCallId；重复答复幂等，过期或底版变化时清晰提示并重新核验。
- 关闭、移动或收起窗口不会自动接受或拒绝。刷新/断线后恢复原待答工具及此前合法决定；医学多提案依次确认、一次整体提交，已答但未写入 Diagnosis 时不能显示为「已保存」。
- 从窗口消失的旧消息可能仍有经许可的结构化长期事实和必要原话证据；UI 不把历史截断宣传为隐私数据擦除。用户不需要看到处理/删除的内部游标。

## 3. Person 个人档案

参考 Penpot 的 Profile 原型，保留其既定的五个分类标签页：**Records、Equipment、Media、Reports、Habits**（R-PS-04）。身份等基础资料（Profile 领域对象）显示在窗口标题区，点击后以 Identity Popover 查看和编辑，不作为第六个标签页。

- Records 展示当前可用的身体记录；缺数据时使用明确的空状态，可继续补充。
- Equipment 展示当前可使用器材及拥有/借用/场所使用关系、可用性；「每周用几次」等习惯属于 BodyState 的 Habits/Records。器材不可用只提示训练计划影响复核，不自动修改处方（PC-D2）。
- Media / Reports 展示统一 UserAsset 的不同分类：同一报告图片只保留一份文件身份。界面分别显示文件可用/删除状态、OCR/解析排队/进行/成功/失败、证据 admissible/needs_review/rejected；核实需展示原件页/位置及必要来源；未准入候选不显示为可信医学证据。基于资料的分析仍由 Chat 发起，不采用旧「上传 → 证据 → 结果」流程（R-PS-03/08）。
- 文件管理应提供清晰不同的「移除原始文件」与「删除文件及关联健康数据」，展示各自保留/擦除范围与进行中/失败/完成反馈。原文件移除后历史结构化观察可保留原准入资格，但须明确显示「原件已移除、当前不可复核」，需要可核验原件的专业放行操作不得将其当作现有临床证明（PC-D7、CD-D4）。
- 标题区 Identity Popover 的极简 Profile 可选编辑；用户时区/单位偏好修改不重写历史事实、原始单位或训练日期（PC-D1）。
- Habits 提供具有时间语义的生活习惯信息。
- 基础资料与身体状态由各自权威数据源提供，不采用演示值作为真实资料。
- Person 不是内部修订管理器，不展示 BodyState 技术修订号（R-PS-02）。

## 4. Diagnosis

Diagnosis 窗口展示**每用户一份当前综合诊断**中的具名医学疾病或综合征（R-DX-01/05/09），而不是症状分组、当次分析报告或未经确认的 AI 候选。

- 主列表只显示 disposition=adopted 的 ConditionEntry；inactive 诊断在历史/详情中可追溯，不默认计入当前诊断数量。术语规范化更新保留医学身份，实质不同医学概念单独成条目。
- 卡片显示医学名称、必要的部位/侧别限定、已有的医学来源、支持/反对证据及鉴别信息、原因分析、处理建议与信息缺口。若只有临床声明而无独立 AI 评估，不强行显示 suspected/likely。
- AI 判断标签只用「疑似（AI 分析）」和「较倾向支持（AI 分析）」；均不表示医生确诊，不由用户选择改变。临床来源另行展示「医生考虑……」等原始不确定性措辞及用户转述/有文件支持的区别。
- 不在 Diagnosis 中展示已缓解/进行中等通用生命周期；症状是否结束来自 BodyState 的 Episode。诊断停用不等于症状结束或临床医学排除。
- 自动检测新事实或来源变化时，可以出现「有新信息，建议复核」及证据摘要；重复变化合并提示，暂不处理不视为拒绝诊断，也不能自动刷新 ConditionEntry 正式证据或结论。
- 多项诊断共享证据时可查看鉴别/替代关系；新诊断被采纳不隐藏另一条 adopted 诊断，除非用户另行接受准确的停用提案。
- 更新成功后一次刷新整个当前 Diagnosis；不展示内部 revision/runId 或报告版本选择器。真实来源、诊断修订与历史采纳决定可以从详情追溯。
- 安全阻断状态（Penpot：Workflow/Assessment Safety Hold）保留，清晰展示停止分析的原因与必要就医提示。

**Chat 中的医学诊断确认工具（confirm_condition）**

- 每项 ConditionProposal 明确类型（新增、同一医学概念更新、采纳状态、诊断关系），展示医学名称、准确目标、变更前后、来源、证据角色、AI 判断、信息缺口及处理建议；缺少具名病名不得伪造诊断提案。
- 用户操作统一为「采纳此提案 / 不采纳 / 继续补充」（具体文案可在 Penpot 再优化）；采纳/拒绝分别记录 accept/reject，不通过按钮选择 suspected/likely；临床来源不通过点击制造「确诊」。
- 停用提案须写明是撤回、被新诊断取代或不再适用，以及准确的目标状态 inactive；用户拒绝时原条目不变。新诊断采纳与旧诊断停用是两个分别确认的决定。
- 一次 Run 多提案时逐项决定、整体原子提交。已决定但尚未提交的卡片有清晰提示；离开 Chat 不等于拒绝，pending 可恢复。
- 在确认过程中补充新事实后，仅受影响的先前决定被标为过期/被取代并重新征求授权；无关决定不要求重选。
- 如果严重安全风险终止 Run，已有决定留档但不生效，Diagnosis 不变；用户需要重新发起分析。成功提交前不显示「已保存」。

**用户直接编辑**（R-DX-13）：只允许根据用户明确请求轻量确认准确的非实质元数据更正或诊断撤回。用户报告「已好了」时记录 BodyState 事实，不显示旧的「标记诊断已缓解」按钮。文案与组件细节见 [Q-19](./open-questions.md)。

## 5. TrainingPlan

每份计划显示自己的当前已接受内容。**展示单位是完整计划，而不是若干部位或抽象训练模块卡片**（R-TP-02）：包括计划目标和频率，以及按顺序排列的热身、正式训练、必要放松；每个动作显示名称、组数、次数/时长。修改某个动作时只更新所属计划，其他计划的窗口内容不变。

Agent 主动建议调整时，Chat 的轻量交互呈现：

1. **影响哪个计划**、受影响的具体动作；
2. **为什么建议复核**及必要的安全提示；
3. **调整前后是什么**，不隐藏重要变更；
4. **接受调整 / 暂不修改** 两项明确结果。

复杂变更可在同一计划窗口中展开审阅；只有接受或明确请求后才更新计划内容，暂不修改或关闭不造成暗改。关闭后建议仍为待决定，可在 Chat 中回到该建议继续选择；建议失效时明确提示原因。

计划有多个课模板（如 A/B 日）时分别展示，每个模板内按热身 → 正式训练 → 按需放松排列。**Draft 是等待用户确认的计划预览**，不能出现在已接受计划列表或直接启动训练。默认频率模式不自动生成日历漏练/补练；仅显式安排才展示日历课次。命中 advisory 时提示注意事项且允许执行；命中 restricted/urgent 时，计划窗口与 Trainer 显示「暂不宜执行」及原因、作用范围、解除条件；非自动解除策略到达复核时点时提示用户复核或记录专业人员放行，解除前仍阻断匹配范围；计划状态与内容不变（R-SAFE-03、R-SAFE-04）。

### 5.1 Trainer 训练执行

规则见 R-EX-01～04、R-SAFE-03。

- 打开指定计划的指定课模板；显示当前动作、第几组 / 共几组、目标次数或时长、休息计时与动作演示。
- 支持开始、暂停、恢复、明确完成或跳过**一组/整个动作**，以及正常完成/提前结束；暂停后恢复回到原动作与组次，关闭窗口不丢失进行中的记录。
- 完成以用户的明确操作或陈述为准；浏览、点击动作卡片、切换到下一项、播放演示均不记为完成。误触可更正且保留审计；同一日多次训练必须为独立实例。
- 训练结束时可记录主观反馈；明确的身体变化按 R-BS-01 写入 BodyState。
- SafetyState 的 advisory 只提示，restricted 对匹配动作/计划安全暂停并显示「暂不宜执行」，urgent 全训练阻断并安全终止；同一用户其它未受限动作可在用户明确选择后继续，不修改计划处方。
- Penpot 中 Workflow/Training Today / Move / Feedback / Paused / Completed 对应执行状态；原型的 **Draft** 画面应改为 PlanProposal 未接受的预览/确认态，不属于 Trainer Session 状态。产品语义已按 TP-D2 确定，Penpot 视觉结构待后续同步。

## 6. 人体交互工具

当 Agent 需要用户指定位置时，允许临时开启点选或涂抹工具，用户在底层人体上完成定位，交互工具将部位和其他用户明确提供的信息返回到原对话。

**选择部位并不自动意味着存在疼痛、异常或临床检查结果。** Agent 需要用户描述现象，才能按 R-BS-01 记录。动作示范属于参考素材，不推断用户真实姿态或负荷（R-EX-02）。

## 7. 平台与辅助功能

- **桌面**：支持多业务浮动窗口，保留可见的人体桌面。必须按实际 Viewer 可见区域验证最小支持窗口宽度，不能仅在 1440px 主画板内验证；标题、卡片与按钮不得横向裁切。
- **窄屏/移动端**：同一业务语义使用适合屏宽的单任务窗口、覆盖层或底部表单；底层人体状态和任务上下文保持可恢复。
- **交互**：Esc 关闭顶层窗口或工具而不丢数据；明确的键盘焦点和返回路径；支持键盘操作和文本部位选择。
- **状态反馈**：加载、错误、未提交、待确认、安全阻断均有可理解反馈；颜色不是状态的唯一表达方式。

## 9. 业务窗口状态索引（供 Penpot 后续精细化）

| 窗口 | 必须区分的业务和 UI 状态 | 归属与未决 |
| --- | --- | --- |
| Chat | 唯一滚动历史窗口；idle/running/waiting_for_user、Ask User 替换底部输入、恢复、已决定未提交、expired、stale、safety_blocked；用户不见清理游标 | [Person/Chat](./domain/person-chat.md)；PC-D4/D5/D9，医学卡片视觉 Q-19 |
| Person | 五分类 empty/loading/populated/error；统一 UserAsset 的文件/处理/证据三状态，原件不可用的历史准入提示；两类删除与身份弹层 | [Person/Chat](./domain/person-chat.md)；PC-D1/D2/D3/D7，CD-D4 |
| Diagnosis | 四个独立状态维度，提案确认、证据变化、历史、安全终结 | [Diagnosis](./domain/diagnosis.md)；DC-021/024 |
| TrainingPlan | 计划 active/paused/completed，Draft/Proposal pending/accepted/rejected/expired，频率或显式日历、独立安全限制 | [Training](./domain/training.md)；TP-D1～D6 |
| Trainer | in_progress/paused/ended、逐组完成/跳过、更正、正常/提前/安全结束、受限范围与复核；Draft 不属于 Trainer | [Training](./domain/training.md)、[Safety](./domain/safety.md)；TP-D7～D12、SAFE-D1～D8 |

这是状态覆盖清单，不要求为每个组合复制 Penpot 静态画板。窗口视觉状态不能冒充后端持久业务状态。

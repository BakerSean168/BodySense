01 · Product loop

从“聊天”走向长期身体状态。

模型回答只是交互层的一部分。真正的产品状态需要能够被用户纠正、被历史追踪、被后续分析精确引用，并在干预之后重新进入反馈循环。

01

Conversation

自然语言描述、结构化追问与安全问题。

02

BodyState

事实、观察、变化、假设和安全状态的 durable projection。

03

Diagnosis

绑定精确 revision、时间上下文和 evidence 的分析。

04

Treatment

可复审、可版本化的干预与训练计划。

05

Feedback

执行、依从性和结果再次写回长期状态。

02 · Engineering

AI 输出必须成为可治理的产品事实。

Durable runtime

Run / Turn / checkpoint 与事件日志让长会话可以 replay、resume，并避免把瞬时 stream 当成业务真值。

Human-in-the-loop

关键缺失信息通过结构化 ask_user interrupt / resume 收集，而不是把所有问题塞进自由文本。

Evidence provenance

RAG 证据与用户 Body Fact 分开建模，诊断可以知道“依据是什么”，也能表达缺口和反证。

Governed model boundary

应用只面对 LiteLLM 网关和稳定模型契约；provider 路由、fallback 与物理凭据不泄漏进领域逻辑。
